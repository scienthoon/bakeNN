# BakeNN versus TFLite Micro on nRF52840DK

This is a physical-target result from FIT IoT-LAB experiment `447609`, not a
host estimate. Both firmwares ran the same 32→16→4 INT8 MLP, the same raw input
bytes, Zephyr 2.7.5, Zephyr SDK 0.13.1, GCC 10.3.0, and a 64 MHz Nordic
nRF52840. Each implementation used 8 warmups followed by 101 timed inferences.

| Implementation | Kernel | Median / p95 cycles | Linked Flash | Linked SRAM | Model arena | Output |
|---|---|---:|---:|---:|---:|---|
| BakeNN portable | generated model-specific C | 8,508 / 8,508 | 20,720 B | 8,192 B | 16 B | `[-8, 10, -15, 3]` |
| BakeNN Cortex-M4 | `cortex_m4.linear_smlad.v1` | 8,872 / 8,872 | 21,360 B | 8,192 B | 16 B | `[-8, 10, -15, 3]` |
| TFLite Micro | selective resolver, reference INT8 FullyConnected | 9,285 / 9,285 | 55,516 B | 9,568 B | 1,024 B reserved / 564 B reported used | `[-8, 10, -16, 4]` |

For this tiny MLP, BakeNN portable used 8.4% fewer cycles than TFLM (about 9.1%
higher throughput), 62.7% less linked Flash, and 14.4% less linked SRAM. The
first BakeNN DSP kernel still used 4.4% fewer cycles than TFLM, but used 4.3%
more cycles than BakeNN portable; AUTO should therefore keep the portable
kernel for a layer this small.

The BakeNN output is byte-exact with its Python INT8 reference. TFLM differed
from that reference in two of four output bytes, by at most one LSB. The
FlatBuffer contains the same INT8 weights, INT32 biases, tensor scales, zero
points, and fused first-layer ReLU; the remaining discrepancy is the arithmetic
behavior of this 2021 TFLM reference path and must not be presented as
byte-exact parity.

The SRAM figures above are final link reservations, not a claim of measured
whole-firmware peak. Main-thread watermarking observed 252 used bytes for
BakeNN and 608 for TFLM, but ISR/system stacks were not watermarked. TFLM's
initial 8 KiB arena probe reported 564 bytes used; near-minimum 592, 704, and
736-byte reservations failed because allocator head/tail placement changed.
The published runner therefore uses a conservative 1 KiB arena.

This comparison uses the reference TFLM integer kernel shipped by Zephyr 2.7's
TFLM module. It is not a TFLM+CMSIS-NN result: that Zephyr integration compiles
the reference kernel list and has no configuration switch for CMSIS-NN. A
current TFLM+CMSIS-NN comparison on a larger Conv-heavy model is required before
making a broad speed claim.
